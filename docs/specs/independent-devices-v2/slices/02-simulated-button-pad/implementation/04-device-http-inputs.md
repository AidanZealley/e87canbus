# Workstream 4: Accept device status and button presses

Status: not started.

## Task packet

### Outcome

Authenticated button pads can post their strict last-reported status and submit one button press
through the controller inbox. No other principal can use either role-specific behavior.

### Scope

- Add `POST /api/devices/status` and `POST /api/devices/button-pad/presses` with exact strict request
  models and `204` success responses.
- Add only the route-table permissions needed by these operations. Enforce button-pad role after the
  common device-principal check; Servotronic remains authenticated but unsupported in this slice.
- Read device ID and role only from `request.state.principal` and stamp status receipt with the
  coordinator UTC clock.
- Store valid button-pad status through Workstream 3's direct repository.
- Make the existing `ButtonPressed` value a supported direct controller input and submit it once via
  the bounded controller inbox with the coordinator monotonic receipt time.
- Add that direct input to both live and simulation controller runtimes. The accepted Slice 1.5
  boundary has no CAN ingress or registry eligibility path.
- Regenerate the coordinator OpenAPI document and Hey API artifacts from source.

### Non-goals

- Configuration SSE, simulator client, retries, deduplication keys or immediate coordinator-driven
  visual feedback.
- Servotronic status, device listing or Wi-Fi presence.
- A second button command path, direct kernel mutation from FastAPI or a compatibility input wrapper.

### Initial ownership

- new device route and internal-handler modules under `hosts/src/e87canbus/api/`
- the device model module established by Workstream 1, extended only with the status and press
  request models owned here
- `hosts/src/e87canbus/api/auth.py` for exact route permissions
- `hosts/src/e87canbus/api/main.py` for router inclusion and clocks
- `hosts/src/e87canbus/kernel/inputs.py`, `hosts/src/e87canbus/kernel/kernel.py` and public kernel exports
- `hosts/src/e87canbus/runners/live.py` and the simulation runtime for admitting the canonical input
- focused API, kernel and authorization tests under `hosts/tests/`
- `protocol/openapi.json` and generated coordinator client artifacts under
  `frontend/packages/coordinator-client/`, regenerated by the repository command

Integration exception: update runtime composition only as required to admit the canonical input.
Do not add the simulated client or alter configuration publisher lifecycle.

### Required seams

- Status parsing selects the role schema after authentication. A body cannot name or spoof role or
  device ID, and a Servotronic principal cannot post a button-pad-shaped status.
- `button_index` is a non-boolean integer from 0 through 15. The route constructs one
  `ButtonPressed(index, observed_at=monotonic_clock())` and submits it once.
- The controller remains the only kernel owner. The HTTP handler never calls the kernel directly.
- The one direct input converges on existing intent/profile logic without transport-specific
  eligibility or a second command type.
- An ambiguous client outcome has no server retry or deduplication mechanism.

### Acceptance criteria

- Valid button-pad status is persisted with authenticated identity and receipt time and returns
  `204`.
- Malformed status, wrong role, console, operator and unauthenticated requests are rejected without
  storage changes.
- One valid HTTP press causes one canonical controller input and one resulting intent evaluation.
- Unassigned and unavailable buttons retain existing kernel behavior.
- A direct press works in both live and simulation runtimes without a device registry.
- Production operation coverage equals the closed authorization table, and generated contract drift
  checks pass.
