# Workstream 5: Deliver durable device configuration over SSE

Status: not started.

## Task packet

### Outcome

An authenticated button pad opens the production configuration endpoint and receives its current
durable envelope followed by complete replacements. One lifecycle-owned service turns current button
state into durable per-device envelopes; the route is the thin authorized edge over it. Neither
blocks the controller thread nor invents generation state outside SQLite.

### Scope

Durable synchronization:

- Add one direct button-pad configuration service using Workstream 1's scene and Workstream 3's
  repository.
- On first contact, atomically get or create the authenticated button pad's envelope from the current
  role-default scene.
- Consume controller `BUTTONS` notifications, compare the feedback-free complete scene with all
  stored button-pad documents, persist changed generations, and publish replacements immediately.
- Fan out the existing single controller notification directly to the browser publisher and this
  service. Do not change `ControllerLoop` into a general event bus.
- Give each subscriber bounded pending output and disconnect saturation or failure without blocking
  the controller or other subscribers.
- Integrate service start and stop into FastAPI lifespan with deterministic ordering.

Public edge:

- Add `GET /api/devices/configuration` with `text/event-stream`, `Cache-Control: no-store`, one
  single-line JSON `data` field per record, blank-line termination and idle comments.
- Authorize only supported device roles. In this slice that means button pad; console, operator,
  unauthenticated and Servotronic principals are rejected.
- Read identity only from `request.state.principal`. The route holds no repository access and no
  second snapshot source.
- Ensure failed sends and request disconnects unregister the subscriber and do not leak route tasks.
- Add the exact nginx location needed for unbuffered device configuration SSE while retaining
  certificate headers and the existing optional-client-certificate server behavior.
- Model the complete button-pad envelope as the endpoint's SSE response and regenerate OpenAPI and
  Hey API artifacts from source.

Design the subscription seam and its one real consumer together. The route's cancellation behavior
is the only evidence that the seam is correct, so do not freeze a subscription signature before the
ASGI response exercises it.

### Non-goals

- Replay, event IDs, `Last-Event-ID`, per-topic streams, presence, status expiry or a generic
  event/publisher framework.
- A shared generic SSE router, a reusable streaming transport, or modifications to the coordinator
  browser stream.
- Servotronic configuration, a cache of authoritative documents, or browser consumption.
- The simulated client, which is Workstream 6.

### Required seams

- Runtime notification performs no SQLite work and awaits no subscriber. It offers only the latest
  relevant immutable snapshot into event-loop-owned work.
- New-device creation and subscription registration are ordered against replacement publication so
  no older scene can follow the initial envelope and no current change can be missed.
- The repository decides whether a document changed and owns generation advancement. The service
  keeps no second generation counter or authoritative document cache.
- One pending complete envelope per subscriber is sufficient. On another change before delivery,
  either safely replace the pending value or disconnect; never grow an unbounded queue.
- The first `data` record comes from the subscription's atomic current envelope; the route does not
  fetch another snapshot or database row.
- Keepalive comments are bytes for the device receive watchdog only. They do not write status,
  update presence or advance generation.
- The outer request task is cancelled or unwound when the service disconnects a saturated consumer,
  matching Starlette's actual streaming task behavior.
- Lifecycle shutdown releases subscribers, route tasks and background tasks within the existing
  configured bound.
- This workstream's route tests are the authority on cancellation and slow-consumer disconnect.
  Workstream 6 drives the stream through a hand-written ASGI loop that could hide a framing or
  cancellation defect, so prove both here against the real response.
- Nginx disables buffering only for this stream and passes the same trusted certificate metadata as
  other routes. Application authorization remains authoritative.
- OpenAPI exposes the real button-pad envelope under `text/event-stream`; no browser-specific live
  union is imported.

### Acceptance criteria

- A valid button-pad principal receives `200`, the exact headers and exactly one complete current
  durable envelope first.
- Console, operator, unauthenticated, unknown-role and Servotronic requests cannot open the stream.
- Repeated contact, reconnect and service restart return the stored envelope without incrementing
  generation.
- A profile or application-state change that alters the feedback-free scene persists and publishes
  one next generation as a one-line JSON SSE record; irrelevant and identical changes do neither.
- Multiple stored button pads receive their own envelopes with independent generations from the one
  current role-default scene.
- Active-only animation and assigned state remain correct on initial and replacement values.
- Idle comments arrive within the approved device receive-watchdog interval, and no event ID or
  replay state exists.
- A slow subscriber cannot block controller work, other subscribers or shutdown, cannot grow memory
  without a bound, and its disconnection closes the real ASGI request without leaking a subscriber
  or task.
- Production operation coverage equals the closed permission table; nginx, served/exported OpenAPI
  and generated-contract checks pass.

## Independent review

- Reviewer: Independent review agent.
- Verdict: Changes required. The normal synchronization and contract checks pass, but two failure paths leave a stream registered or permanently stale.
- Required findings:
  1. A failed send before the first event leaks the subscriber. `stream_configuration()` registers it before returning the response (`api/routes/devices.py:49-52`), while `events()` unregisters only in the async generator's `finally` (`api/internal/device_configuration.py:113-129`). If ASGI `send` raises on `http.response.start`, Starlette never starts that generator. I exercised the production app with an ASGI sender that raises `OSError` on its first call: the request failed and `subscriber_count` remained 1. The existing route tests cover disconnection only after the first record. Ensure response failure and early disconnect close registrations even if iteration never starts, then cover that path through the real response.
  2. One SQLite publication error permanently disables configuration updates. `_run()` has no error handling around `list_button_pad_configurations()` or `replace_configuration_if_changed()` (`api/internal/device_configuration.py:131-159`), and `subscribe()` considers any non-`None` task running (`:83-85`). With one injected `DeviceStateStorageError` from `list_button_pad_configurations()`, the worker task finished; after restoring the repository and changing the profile again, the stored generation remained 0. Existing clients can continue receiving keepalives while their document is stale. Fail or recover the service explicitly so it cannot advertise a healthy stream after publication has stopped, and test a publication failure.
- Optional observations: None.
- Questions: None.
