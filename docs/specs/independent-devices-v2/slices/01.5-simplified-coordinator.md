# Slice 1.5: simplified coordinator

- **Status:** Approved
- **Date:** 2026-09-18
- **Depends on:** [ADR 0018](../../../decisions/0018-simplify-coordinator-before-independent-devices.md),
  [Architecture and boundaries](../architecture-and-boundaries.md) and completed browser SSE work

## Outcome

The coordinator no longer contains a project-device CAN platform or pretends to control hardware
that has moved to independent devices. Its kernel and runtimes retain only the responsibilities
needed by the planned system.

This slice intentionally leaves a period with no button-pad input and no Servotronic output. Neither
device is in use. Slice 02 adds the independent simulated button pad, while Slice 06 later adds the
independent simulated Servotronic controller.

## Coordinator responsibility test

Every retained kernel input, state field, timer, commit value and diagnostic must support at least
one of these responsibilities:

1. Decode and retain vehicle observations.
2. Apply operator and button intents to desired coordinator state.
3. Manage active profiles and curves.
4. Publish complete projections for browser SSE and device configuration.

Authentication, durable device envelopes, last-reported status and SSE subscribers are application
services outside the kernel. A later button press enters the existing ordered input path, but its
HTTP request does not enter the domain.

## Remove the high-beam flash feature

Remove `start_high_beam_strobe` from the button command catalogue, profile API, editors and generated
contracts. Remove its coordinator state, timing, simulated vehicle command, lighting live projection
and tests.

This prototype does not migrate existing application databases. Replace them after this slice. A
fresh database contains one selected profile named `Default` with sixteen unassigned slots. The
seeded profile preserves the useful non-empty catalogue and selected-profile invariants without
encoding any product command or assignment. Do not retain a deprecated command parser or hidden
no-op action.

This does not define future headlight actuation. A later feature may add a capture-backed vehicle CAN
command directly to button-pad firmware or to another named component.

## Remove button-pad transport behavior

Remove button-event CAN decoding, LED program and feedback effects, button-pad ISO-TP, registry
gating, old firmware and the simulated NeoTrellis peer.

Remove coordinator-owned press acknowledgement and failure feedback. This includes feedback state,
deadlines, blink effects and output-failure correlation. Button profiles, assignment and active-state
semantics remain. There is no button input between this slice and Slice 02.

The browser does not receive raw button program bytes. It retains only profile and desired
application state that current screens use. Slice 02 creates the independent JSON scene projection.

## Remove Servotronic execution behavior

Remove coordinator-side assistance calculation, periodic actuator commands, curve transfer,
activation acknowledgement, observed output, watchdog simulation, availability gating and fallback
effects. Delete the old firmware and simulated CAN peer.

The coordinator retains desired steering mode, the UI's selected manual level, maximum override and
the active curve. It accepts changes without a connected-device predicate. Until Slice 06, these
values produce no Servotronic output and claim no applied hardware state.

Vehicle speed remains a coordinator observation for the browser. It no longer drives steering
output or a steering-specific fallback.

## Remove the shared device-CAN platform

Delete:

- the generated custom protocol source, outputs, generator and CI check;
- device discovery, heartbeat, acknowledgement, sessions and catalogue metadata;
- coordinator-device ISO-TP and its Python and embedded dependencies;
- custom project CAN IDs and device-source deployment choices;
- project-device simulator controls, topology and diagnostics;
- old button-pad and Servotronic firmware projects; and
- dead configuration, dependencies, tests, exports and documentation.

Delete `DeviceRole` with its current consumers. Slice 02 introduces a new role type at the
certificate and HTTP authorization boundary where it first has a real use.

## Simplify the coordinator

With all current actuator effects removed, delete the generic effect union, `EffectRequest`,
`EffectExecutor`, effect failure inputs and `Commit.effects`. Remove exact deadline scheduling if no
retained behavior needs it. A periodic tick may remain for telemetry freshness.

Remove device and steering-actuator health, the `devices` and `lighting` state topics, adapter
projections with no remaining consumer, and duplicate revision or state-change values that do not
serve browser publication or another retained responsibility.

Keep the bounded single-owner controller loop, vehicle frame decoding, network receive health,
inbox overflow handling, immutable desired state, profile activation and complete snapshot
publication. Keep live and simulated runtimes separate, but narrow their common contract to the work
they still perform. The simulator retains vehicle input needed by current screens and tests; it has
no project-device peer graph.

## CAN transmission boundary

Keep `CanFrame`, receive/transmit endpoint protocols, SocketCAN's basic send operation and in-memory
bus transmission. The live coordinator grants no transmit network and has no application command
that sends a frame.

Do not add an empty vehicle-action union, output service, encoder registry or future command hook.
A later capture-backed vehicle action can add a direct typed encoder and a bounded transmitter
without restoring the removed effect system.

## Outside this slice

This slice does not add device authentication, HTTP routes, configuration persistence, device SSE,
new firmware, a simulated independent device or physical vehicle actuation. It does not redesign
manual steering levels or the active profile APIs.

## Acceptance

The slice is complete when:

- no coordinator-device CAN protocol, registry, ISO-TP, firmware or simulated peer remains;
- no coordinator button-feedback, Servotronic execution or high-beam flash behavior remains;
- no legacy device role, source, lifecycle, catalogue or deployment type remains;
- the effect executor and effect-bearing commit contract are gone;
- the kernel contents can each be traced to one of the four retained responsibilities;
- desired steering state, active curves and button profiles still work without device availability;
- a fresh database seeds and selects one `Default` profile with sixteen unassigned slots;
- existing prototype databases are intentionally replaced rather than migrated;
- browser and generated contracts contain no deleted device, applied-output or lighting fields;
- vehicle CAN decoding, vehicle telemetry, profile operations and browser SSE still work; and
- no unused transmit abstraction or configured live CAN authority remains.
